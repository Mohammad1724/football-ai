# نتیجه اصلاحات بازبینی — نسخه ۰٫۳٫۰

## هشت مرحله انجام‌شده در کد

۱. **اتصال تاریخچه:** لیگ و تیم در import و fixtures از یک قرارداد شناسه استفاده می‌کنند. مهاجرت Room از نسخه ۱ به ۲، شناسه‌های CSV را اصلاح و رکوردهای تکراری را با حفظ جدیدترین داده ادغام می‌کند. تاریخچه قدیمی API که نوع امتیاز آن معلوم نیست حذف نشده، بلکه با source شروع‌شونده با `legacy-unverified:` قرنطینه شده است؛ برای استفاده دوباره باید تاریخچه API وارد شود. منابع مختلف همچنان عمداً با هم تطبیق خودکار داده نمی‌شوند.

۲. **پیش‌بینی معتبر:** فقط مسابقه SCHEDULED با kickoff آینده اجازه ایجاد پیش‌بینی قبل بازی دارد. مسابقه تمام‌شده فقط پیش‌بینی ذخیره‌شده قبلی را نشان می‌دهد؛ پیش‌بینی جدید ساخته نمی‌شود. cutoff و snapshot پس از محاسبه سنگین دوباره بررسی می‌شوند. اولین پیش‌بینی قبل بازی به ازای مسابقه/نسخه مدل تغییرناپذیر است؛ کنترل تکرار داخل تراکنش DAO نیز انجام می‌شود.

۳. **تازگی داده زنده:** سقف عمر نتیجه و آمار live دو دقیقه است. امتیاز نامعلوم به ۰–۰ تبدیل نمی‌شود؛ آمار قدیمی از ورودی حذف می‌شود. شکست refresh، خروجی live را پاک می‌کند و پیام خطا نمایش می‌دهد. وقتی صفحه دیده می‌شود، تازگی snapshot نیز دوره‌ای کنترل می‌شود؛ پیش‌بینی قبل بازی همچنان در حالت آفلاین، با رعایت وضعیت و زمان، قابل محاسبه است.

۴. **زمان و محاسبات live:** تخمین دقیقه از ساعت دیواری حذف شد؛ HALF_TIME دقیقه ۴۵ است. اگر دقیقه معتبر نباشد یا بازی هنوز زنده در دقیقه ۹۰ به بعد باشد و افق وقت تلف‌شده معلوم نباشد، پیش‌بینی متوقف می‌شود. موتور در افق دقیقاً صفر، احتمال گل آینده صفر دارد. در نبود shots-on-target، کل شوت با میانگین کل شوت مقایسه می‌شود.

۵. **قواعد امتیاز:** فیلد scoreScope به داده provider و دیتابیس اضافه شد. وقت اضافه/پنالتی، نتایج اداری، بازی رهاشده و امتیاز نامعلوم وارد آموزش یا تسویه بازارهای ۹۰ دقیقه نمی‌شوند. این اصلاح به معنی پشتیبانی کامل از بازار وقت اضافه یا استخراج امتیاز ۹۰ دقیقه همه providerها نیست؛ موارد نامطمئن محافظه‌کارانه کنار گذاشته می‌شوند.

۶. **ارزیابی:** آمار ذخیره‌شده فقط نسخه فعلی مدل و اولین snapshot معتبر قبل بازی به ازای هر مسابقه را می‌شمارد؛ live و نسخه‌های قبلی با آن مخلوط نمی‌شوند. Brier مدل برای مقایسه با بازار روی دقیقاً همان بازی‌های دارای ضریب محاسبه و تعداد آن‌ها نمایش داده می‌شود. بک‌تست گروه‌های هم‌زمان را قبل از واردکردن نتیجه ارزیابی می‌کند. چون زمان واقعی پایان در داده تاریخی موجود نیست، فاصله محافظه‌کارانه حداقل ۱۲۰ دقیقه از kickoff برای در دسترس‌بودن نتیجه در نظر گرفته شده است؛ این فرض جای timestamp واقعی پایان را نمی‌گیرد.

۷. **چرخه نتایج CSV:** import نتایج اکنون مسابقه مرتبط را نیز FINISHED می‌کند؛ sync عمومی نتایج مسابقات CSV منتظر نتیجه را دریافت می‌کند. ارتباط پیش‌بینی با شناسه قبلی مسابقه حفظ می‌شود. شناسه جدید fixture به تاریخ و دو تیم وابسته است، نه ساعت شروع؛ تغییر ساعت در همان روز رکورد دوم ایجاد نمی‌کند. **تغییر روز یک بازی به‌دلیل تعویق عمداً با حدس تطبیق داده نمی‌شود**؛ CSV شناسه ثابت provider ندارد و بعضی لیگ‌ها چندبار یک ترکیب میزبان/میهمان را در یک فصل تکرار می‌کنند. موارد مبهم به تطبیق صریح نیاز دارند.

۸. **اجرا و نگهداری:** آموزش مدل به Dispatchers.Default و پاک‌کردن دیتابیس به Dispatchers.IO منتقل شده است. پیش از پاک‌کردن داده، background sync غیرفعال/لغو می‌شود و خطای ذخیره‌سازی در UI نمایش داده می‌شود. refresh ستون‌های metadata مربوط به آمار و ترکیب را حفظ می‌کند. timestamp ذخیره live فقط پس از persist تغییر می‌کند. polling به lifecycle صفحه متصل شده است. Cancellation در ApiClient دوباره پرتاب می‌شود تا به خطای شبکه معمولی تبدیل نشود.

## ایراد اضافه‌ای که هنگام اصلاح پیدا شد

کلید اصلی `prediction_markets` شامل خط گل نبود؛ بنابراین OVER 0.5، 1.5، 2.5 و 3.5 یکدیگر را هنگام ذخیره جایگزین می‌کردند. کلید به `(predictionId, sortOrder)` تغییر کرد و مهاجرت جدول اضافه شد. رکوردهای قبلاً ازبین‌رفته قابل بازسازی نیستند؛ رکوردهای باقی‌مانده حفظ می‌شوند.

## اعتبارسنجی انجام‌شده

- موتور با **Kotlin 1.9.24 و Java 17** کامپایل شد.
- **۵۹ بدنه تست موتور**، شامل تست‌های قدیمی و regressionهای جدید، با harness مستقل JVM اجرا و موفق شدند.
- **۳۱ بدنه تست مستقل اپ** مربوط به parserهای CSV، فصل‌ها و PredictionPolicy اجرا و موفق شدند. در این اجرای ایزوله، annotationهای Room و HTTP client با stub جایگزین شدند؛ هیچ درخواست واقعی شبکه‌ای انجام نشد. این اجرا معادل تست Room یا Android نیست.
- **۴ تست SQLite** از SQL واقعی migration و query گزارش عملکرد گذشتند: canonical شدن ID و ادغام تکراری‌ها، قرنطینه داده نامطمئن، حفظ خطوط متعدد بازار و cascade، و حذف تکرار/live/نسخه قدیمی از آمار. اجرای مجدد: `python3 scripts/check_review_sql.py`.
- repositoryهای تغییرکرده نیز با Kotlin و stub وابستگی‌های Android/Room/serialization بررسی نوع و کامپایل شدند؛ این بررسی جایگزین KSP/Room-generated code نیست.
- XML منابع parse شد و `git diff --check` بدون مشکل گذشت.
- سه تست instrumented در `RoomRegressionTest` برای حفظ metadata، خطوط بازار و immutable snapshot اضافه شد، اما **اجرا نشده‌اند**.

## کارهای لازم پیش از انتشار

۱. اجرای واقعی `gradle :engine:test :app:testDebugUnitTest :app:assembleDebug` در CI با ابزار Android.
۲. اجرای `gradle :app:connectedDebugAndroidTest` روی emulator یا دستگاه.
۳. نصب نسخه جدید روی نسخه ۰٫۲ با دیتابیس واقعی و بررسی اعتبارسنجی Room migration، صفحه فارسی/RTL، lifecycle و خطای شبکه.
۴. بررسی پاسخ واقعی providerها با کلید خود کاربر؛ این محیط دسترسی شبکه به providerهای فوتبال نداشت.

**APK در این محیط ساخته نشده، تغییرات push/merge نشده‌اند و ادعای تأیید کامل روی گوشی یا سودآوری مدل نداریم.** نسخه اپ به `0.3.0`، versionCode به ۶ و نسخه مدل به `football-ai/engine-1.1.0` افزایش یافته است.
