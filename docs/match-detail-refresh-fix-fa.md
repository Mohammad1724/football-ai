# «داده پیدا نشد» در صفحهٔ مسابقه — چه بود و چه شد

## چیزی که دیده می‌شد

1. مسابقه را باز می‌کنی → زیر تب «تحلیل» می‌نویسد **داده پیدا نشد** و دکمهٔ «تلاش دوباره».
2. همان دکمه را می‌زنی → تحلیل می‌آید.
3. دکمهٔ به‌روزرسانی را می‌زنی → دوباره **داده پیدا نشد**.

## دلیل واقعی

تحلیل مشکل نداشت. ترتیب کارها مشکل داشت.

صفحهٔ جزئیات پیش از هر چیز تلاش می‌کرد همان بازی را از منبع بخواند. منبع‌های بدون کلیدِ این برنامه — ESPN و football-data.co.uk — **کل برنامهٔ یک روز** را منتشر می‌کنند، نه یک بازی تکی. پس درخواست «یک بازی» جواب «پیدا نشد» می‌گرفت، و صفحه این جواب را خطای کشنده تلقی می‌کرد:

```kotlin
is Outcome.Failure -> {
    _state.update { it.copy(lastError = result.error, prediction = null, isLoading = false) }
    return false
}
```

و بعد `load()` با `return@guarded` بیرون می‌زد، یعنی **پیش‌بینی هرگز محاسبه نمی‌شد**. در حالی که پیش‌بینی به داده‌های ذخیره‌شده نیاز دارد و به شبکه کاری ندارد — به همین دلیل «تلاش دوباره» موفق می‌شد: آن مسیر پیش‌بینی را صدا می‌زد، نه شبکه را.

نسخهٔ قبلی برای بازی‌های غیرزنده یک استثنا داشت (`if (!isLive) predict()`) و همین باعث می‌شد بازی تمام‌شده درست کار کند ولی بازی **زنده** همیشه خطا بدهد.

## چه تغییری کرد

| لایه | تغییر |
|---|---|
| قابلیت منبع | `ProviderCapabilities.singleMatchRefresh`. ESPN و football-data.co.uk آن را `false` اعلام می‌کنند، پس هیچ صفحه‌ای سؤالی که منبع نمی‌تواند جواب دهد نمی‌پرسد. |
| همگام‌سازی | `refreshMatch` برای این منابع به‌جای «یک بازی» همان **روزِ بازی** را می‌گیرد: یک درخواست برای یک روز. روزی که بیرون از بازهٔ منتشرشده باشد چیزی نمی‌نویسد و این خطا نیست. |
| صفحهٔ جزئیات | شکست به‌روزرسانی دیگر صفحه را خالی نمی‌کند: یک نوار کوتاه بالای تحلیل می‌گوید «به‌روزرسانی نشد؛ داده‌های ذخیره‌شده نمایش داده می‌شود»، و تحلیل در هر حالت محاسبه می‌شود. |
| داده کهنه | بررسی «زندهٔ کهنه» فقط جایی اجرا می‌شود که ردیف واقعاً قابل به‌روزرسانی باشد؛ قبلاً هر ده ثانیه خطا می‌داد برای داده‌ای که کسی نمی‌توانست تازه کند. |
| ردیابی زنده | با همین مسیر (برنامهٔ روز) حالا برای این منابع هم کار می‌کند. |

## یک باگ صادقانه که در همین مسیر پیدا شد

نتیجهٔ بازی که منبع هنوز منتشرش نکرده بود، به‌صورت **۰ - ۰** چاپ می‌شد (`homeGoals ?: 0`)، و پیش‌بینی «در جریان بازی» هم روی همان ۰-۰ ساختگی اجرا می‌شد.

- نمایش: `Formatters.scoreOrNull(...)` — اگر نتیجه نباشد، خط تیره (`—`)، نه صفر.
- مدل: پیش‌بینی در جریان بازی فقط وقتی اجرا می‌شود که نتیجهٔ فعلی معلوم باشد؛ وگرنه مدل پیش از بازی استفاده می‌شود.

## آزمون‌ها

- `FormattersTest`: نتیجهٔ ناقص هرگز صفر نمی‌شود.
- `EspnScoreboardTest`: منبع اعلام می‌کند که یک بازی تکی را نمی‌تواند تازه کند.
